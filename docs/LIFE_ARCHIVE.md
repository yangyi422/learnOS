# 生活档案 V0.1

## 定位和使用

`/life` 是独立的生活空间，沿用现有认证与 UI，不更改应用名、Docker 配置或学习/项目架构。

- **时间线**：用户主动创建事件；按发生日期倒序。支持补录、阅读详情、编辑、删除，按任一领域与里程碑筛选。名称与日期必填，描述、主/次领域、目标、链接可选。最多两个不同领域，次领域依赖主领域。
- **长期目标**：名称、为什么重要、当前判断、五种状态。可选关联一个现有项目、一个领域和一个外部链接。目标独立存在，不随项目完成自动实现。已实现/已结束目标仍在列表中，可再次查看历史。
- **阶段变化**：主动记录进展/决定与原因；修改状态时事务内生成历史。编辑当前判断时可以勾选保存为阶段记录；普通标题编辑不生成历史。记录日期采用用户本地日历，状态变化日期可修改。
- **Inbox**：增加“保存为生活事件”，保留原文为描述，补充名称与日期。保存成功才移出待整理，已处理列表可重新打开事件。不影响任务与轻量记录去向。
- **成果**：项目列表可以明确标记项目完成，再点击“收录到生活档案”；课程档案页在所有实际课程和活动蓝图节点均完成或跳过后可以手动确认结业，再收录。结业明确说明包含跳过的课，不提高掌握度；学习覆盖度百分比不替代正式结业状态。已有正式 completed 课程也可收录。默认里程碑，仍可编辑。

八个领域：财务与资产、身心健康、人际与关系、工作与创造、学习与认知、兴趣与体验、居住与生活环境、时间与生活节奏。预设分类，不新增一级导航或分类管理。

来源目前没有独立完成时间戳，因此成果的发生日期默认本地当天，并提示用户确认；不将更新时间当作完成日期。

## 数据与接口

Schema 21 仅新增 `life_events`、`life_goals`、`life_goal_entries` 和索引，不改写旧数据。

- 事件保存文字日期 `YYYY-MM-DD`，避免 SQLite DATE 扫描与 UTC 转换；主/次领域为校验后的预设键。
- 事件可关联一个目标。目标可关联一个真实项目 ID，保存时事务内验证归属和存在性；已归档项目仍可关联。
- 事件来源包含真实 `source_type/source_id`、标题快照和内部唯一键。快照不是项目/课程的复制系统；来源删除或归档不会级联删除生活档案。详情展示来源不可访问或已归档的信息。
- 所有查询/变更限制当前用户；目标历史通过已验证的目标归属授权。
- 直接创建事件/目标、阶段记录必须携带 `creation_key`。唯一索引与事务保证请求重放不会创建多个事实。相同键改变正文返回冲突，避免覆盖已保存内容。
- Inbox 转事件在一个事务内条件认领 Inbox、创建事件、写入处理去向。失败全部回滚；同一来源同样内容重放返回原事件，改内容/更换去向返回冲突。并发 SQLite 锁冲突可重试，不靠禁用按钮保证唯一性。
- 来源信息只在创建时由后端读取，更新事件不会更换来源。相同来源当前只能存在一个事件，包括取消里程碑标记后的事件。
- 用户明确删除事件是真正删除。原始来源保留；项目/课程可以重新手动收录，Inbox 保持已处理避免原文重新进入待整理。其查看入口会明确提示事件不存在。目标通过已结束状态保留，不提供破坏历史的删除操作。
- 链接复用 `internal/links`、`ExternalLink`、`LinkedText`，不渲染不可信 HTML。支持 http/https 与受控 Obsidian open URI，可复制完整原始链接。后端不访问本地 Vault。

受保护 API：`/api/v1/life/events`、`/life/events/:id`、`/life/goals`、`/life/goals/:id`、`/life/goals/:id/entries`、`/life/sources/:type/:id`；Inbox 转换为 `/inbox/:id/convert-to-life-event`；手动结业为 `/courses/:id/graduate`。无 AI 调用。

## 迁移、备份与回退

启动沿用 `database.Open`：旧库先进行整库 `VACUUM INTO` 备份，再执行可重复 AutoMigrate，成功后更新 schema metadata。SQLite 整库备份/恢复天然覆盖三张新表；JSON/Markdown 导出同步增加生活档案、目标与历史。

升级无需新配置或依赖，不导入历史任务、项目或学习记录。可以保留升级后库并回退旧程序，新表不被旧代码读取；旧 UI 对 Inbox 的 `life_event` 去向无法完整展示，但原文及关联元数据仍保留。需要完整回退体验时停止服务并按既有恢复流程恢复迁移前备份，恢复会丢弃升级后新增事实，先导出/备份。

## 验证与边界

后端真实 SQLite 测试覆盖 CRUD、日期排序、双领域筛选、用户隔离、无效链接、目标历史、来源资格、并发/重放、注入失败回滚、可重复迁移与备份内容；HTTP 测试检查认证和持久化 API。浏览器测试验证阅读/编辑、失败输入保留、关闭保护、Inbox/成果入口、目标历史和四种宽度及深浅主题。

V0.1 不提供 AI 人生建议、自动总结、打卡、自动任务导入、Obsidian 同步、复杂关系图或新搜索引擎。数据规模较大时可再增加时间线分页；当前展示所有收录事件。Obsidian 客户端唤起需在用户设备人工确认，自动测试仅验证 URI 与复制入口。


## V0.1 第二轮：阅读与变化历程

继续复用 `why/current_note/updated_at` 和现有阶段记录，无新增字段、表、依赖或 Schema 版本变化。旧记录按原日期保留，详情按发生日期和 ID 倒序排列。

- 目标概况区分稳定的个人动机和当前判断；空字段使用短提示。列表只展示已有摘要和真实更新时间。
- 变化历程展示完整内容、日期、原因、原始状态前后值。可新建、编辑、修改日期及确认删除。
- 新增 `PUT /api/v1/life/goals/:id/entries/:entryId` 与 `DELETE` 同路径。验证目标归属与记录实际所属目标。编辑不改变历史状态前后值或创建时间；删除状态记录不回退当前目标。阶段变更与目标 `updated_at` 在事务内提交，任一步失败全部回滚。
- 记录创建仍使用原请求键去重；编辑保留创建身份。空正文只允许已有状态变化记录，普通阶段记录必须有正文。编辑目标普通文字不会额外产生历史。
- 时间线保留年月分组和原发生日期顺序；按真实关联 ID 展示目标名称、来源标题或已有外部资料名称。不增加假摘要或无来源的标签。
- 弹窗继续居中、默认阅读，正文自然滚动，底部按钮保持可访问。Esc 关闭先校验未保存修改；关闭返回触发卡片，触发卡片已消失时返回当前视图按钮。相关事件跳转也检查未保存记录。
- 保存成功立即更新列表/记录，再刷新后端详情；刷新失败保留已保存内容并提示。目标更新日期最终来自数据库，不用浏览器时间冒充服务端状态。

人工体验重点：长期目标卡片的摘要与更新日期；目标详情动机/当前判断及长篇阶段记录；手机端事件详情滚动、Esc/关闭焦点与有修改时的确认。


## 财务子页导航（V0.2-A 第二轮）

生活与财务共享轻量面包屑。生活视图、领域和里程碑条件写入 URL；进入财务时以 life_view、life_domain、life_milestones 携带来源上下文，返回生活恢复原视图。财务子 Tab 与明细条件使用查询参数，月份/分类/标签可下钻。滚动位置只保留在当前应用内存，不写入持久存储；普通保存后读取不重置当前滚动。详见 [FINANCE_ARCHIVE.md](FINANCE_ARCHIVE.md)。

## V0.2-C 财务参考

长期目标详情可关联已有资产快照，保留判断日期和说明；不改变目标或产生阶段历史。查看快照和反向目标入口复用原页面及弹窗。数据规则见 [GOAL_FINANCIAL_REFERENCES.md](GOAL_FINANCIAL_REFERENCES.md)。

## V0.3-A 月度回顾

生活内增加月度回顾入口，按真实记录组织行动、学习、生活、财务与目标变化。保存时冻结事实，个人心得独立编辑，重汇总先预览确认并保留旧事实；不进行效率或生活评分。统计边界、时间字段和数据规则见 [MONTHLY_REVIEW.md](MONTHLY_REVIEW.md)。
