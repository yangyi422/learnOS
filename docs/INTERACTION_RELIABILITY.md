# 关键交互可靠性契约

本文记录新建领域、移动导航和探索领域选择器的可验证行为。这里只收紧交互边界，不改变课程、Lesson、知识节点或学习状态的数据模型。

## 新建学习领域

- 领域名称必填，去除首尾空白后为 2–50 个字符。
- 学习原因必填，去除首尾空白后为 10–4000 个字符。
- 期望深度必须是 `overview`、`foundation` 或 `systematic`。
- 前端错误显示在对应字段下；本地校验失败不得调用 API。
- 前端提交前发送规范化后的值，提交期间禁用按钮，并在异步入口再次检查互斥状态。
- 后端重复执行同一规则。无效输入返回 HTTP 400 和结构化错误码 `DOMAIN_INPUT_INVALID`，不得只把 HTTP 状态码呈现给用户。

这些校验发生在 Draft 创建前，不迁移、覆盖或删除已有 Draft、Course 与学习记录。

## 移动导航抽屉

- 打开后将焦点移入第一个菜单项；Element Plus Drawer 的焦点陷阱阻止键盘焦点进入遮罩后的页面。
- Escape 和点击遮罩都关闭抽屉；普通关闭后焦点回到汉堡按钮。
- 选择菜单项时先标记导航焦点目标，再切换路由并关闭抽屉；关闭动画完成后焦点进入新页面的一级标题。
- Drawer 不启用 body 滚动锁。关闭后遮罩不可见，页面不能继续变暗。

## 探索领域选择器

- 选择器必须有可见标签“当前探索领域”和可访问名称，控件保持明确宽度并显示当前课程名称。
- 每次领域切换先递增选择版本，清空推荐、问题和陌生知识结果，并显示“切换中…”状态。
- 雷达与问题请求只有在请求版本和当前 `courseID` 都匹配时才能更新页面；过期响应被丢弃。

## 回归门禁

- Vitest 覆盖领域表单规范化、空白输入、长度和合法深度。
- Go service 覆盖空输入不持久化和输入边界，handler 覆盖结构化 400。
- Playwright 覆盖空表单零请求、连续点击单请求、抽屉的 Escape/遮罩/导航关闭与焦点恢复、探索选择器在 375/768/1440px 的可见名称，以及切换加载态和旧响应隔离。
