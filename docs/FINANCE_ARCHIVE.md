# 财务档案 V0.2-A

钱迹负责原始记账，LifeOS 只保存只读档案、分析收支和追溯原始字段。入口为生活空间 → 财务档案（`/life/finance`）。不连接 AI，不计算净资产，不提供手工记账。

## 导入

上传钱迹 UTF-8 CSV（支持 BOM），使用原始 18 列及顺序：ID、时间、分类、二级分类、类型、金额、币种、账户1、账户2、备注、已报销、手续费、优惠券、记账者、账单标记、标签、账单图片、关联账单。Go `encoding/csv` 处理引号、逗号、字段内换行。文件上限 10 MB、50000 条、单字段 64 KB。非法 UTF-8、表头、重复 ID、时间、金额、币种等全部在后端校验；返回物理行号和原因，最多展示 100 条错误。任何错误都禁止正式导入，不会跳过错误行后悄悄导入剩余行。

时间接受 `YYYY-MM-DD HH:mm:ss` / `YYYY-MM-DD HH:mm` / `YYYY-MM-DD`，按钱迹原始本地日历解释，不做 UTC 转换。金额为最多两位小数、最多 10 位整数的十进制，拒绝浮点科学计数及多余精度。包括负数退款；按原始金额符号汇总。手续费及优惠券单独验证精度，仍按原始字段保留，不再次加减；已报销字段不自动抵销原交易。原始 18 字段完整保存在 JSON 中；标签按 `#` 拆分、去空白、同一账单同名标签去重，原标签串同时保留。

每次选择相同的来源账本名称，后端以 `(用户 ID, 账本名称)` 识别来源，以 `(账本 ID, 钱迹交易 ID)` 唯一识别交易。不同来源的相同 ID 互不覆盖。内容哈希包含全部原始字段；新增创建，变更更新，未变化不写交易。绝不按金额、日期自动匹配 ID。若同一范围同时出现新增和缺失 ID，预览警告用户核对 ID 稳定性；不稳定 ID 的自动匹配策略尚未实现，应在确认来源后再导入。

预览存为待确认批次，有效期 24 小时。确认只接收批次 ID 和移除确认选项，不信任浏览器传入的交易或金额。账本 revision 防止陈旧预览覆盖新导入。重复确认同一成功批次返回该批次；同文件再次预览和导入可创建审计批次，但不重复交易或改变未变化交易的内容/时间戳。事务内写交易、完整前后快照、批次状态和账本版本，任何错误整体回滚。

### 缺失与撤销

默认增量导出不推断缺失，也不删除。用户可以明确声明文件是某个日期范围内、未筛选的完整导出：服务器验证日期范围及全部新交易在范围内，列出范围内缺失 ID。CSV 本身无法证明完整性；只有再次明确确认“完整范围、稳定 ID、移除缺失”并确认弹窗后才移除。范围外数据不受影响。

撤销从同一账本最近有效批次开始，倒序恢复新增、更新、移除的交易及原始字段、标签、内容哈希、来源批次和时间戳。较早批次须先撤销后续批次，避免破坏有效覆盖。撤销失败事务回滚；重复撤销已撤销批次是幂等操作。未确认预览不影响交易。

## 统计口径

- 单次统计只选择一种币种，多币种不相加；首次遇到多币种由界面选择单币种再查询。
- 收入/支出分别按类型对整数分求和；差额为收入减支出，转账不计入两者。差额不是资产增长。
- 分类统计仅统计支出，二级分类包括无二级分类；分类占比的分母是本期间、本币种总支出。负数退款保留正负，分母不大于零时不展示占比。
- 标签金额是该标签对应账单支出，同一交易在总支出只计一次，但可以在多个标签内出现；标签金额不可加总为消费。没有标签的交易仍在总支出内。
- 年/月和自定义范围使用本地日期，当前及未来月份提示期间未结束；已结束期间不保证无漏账。全部时间只描述已导入记录，不标为未结束。覆盖期间是账本内交易实际起止日期，不证明导出完整性。
- 无记录显示空状态，不展示余额或净资产。月度趋势只显示真实有账目的月份。
- 明细使用 SQLite 条件筛选与分页（30 条/页，API 最大 100），标签匹配使用 JSON 数组精确成员匹配，不使用模糊子串。备注关键词参数化查询，不当作 SQL 执行。

## API 与隐私

所有接口位于现有认证 `/api/v1/finance` 路由组：

- `GET /ledgers`
- `POST /preview`（multipart：file、ledger_name、complete_scope、scope_from、scope_to）
- `POST /batches/:id/import`（remove_missing、confirm_missing、confirm_stable_ids）
- `POST /batches/:id/undo`
- `GET /ledgers/:ledger/summary`
- `GET /ledgers/:ledger/transactions` 和 `GET /ledgers/:ledger/transactions/:id`
- `GET /ledgers/:ledger/batches`

所有读写先检查账本用户归属。交易没有创建、编辑或删除 API。原始文字以 Vue 插值展示，不执行 HTML、图片或外链内容。上传只发送到用户自托管服务器，不发给 AI，文件不放静态目录、不保存原文件路径。财务仓储禁用 SQL 参数日志，财务请求禁用 Gin 访问日志，防止备注搜索词进入日志。错误响应只给安全原因，不暴露 SQL 或堆栈。

## Schema 22、备份与回退

可重复 AutoMigrate 新增 `finance_ledgers`、`finance_transactions`、`finance_batches`、`finance_changes`，不改写旧生活、任务、Inbox 或课程。启动升级前沿用 SQLite VACUUM 快照。SQLite 完整备份和恢复覆盖全部财务表，包括撤销快照和预览载荷；JSON 导出包含交易原始字段及快照，Markdown 提供交易索引。备份含私人财务信息，应使用现有受保护下载入口。旧程序可忽略新增表；需要完整回退数据时恢复迁移前备份。

## 第二轮 UI 与交互

不变更 API、Schema 22 或收支口径，不写入已有交易，不引入依赖。

- 顶部以账本、统计期间、币种组织上下文；概览保留收入、支出、收支差额，金额使用整数分 / BigInt 格式化。显示账本实际起止日期、最新账目日期、最新导入时间与文件条数。覆盖起止日期属于整个账本，不代表所选期间的数据完整性。
- 月度横条共用比例尺、明确收入/支出图例及上限，增加准确差额、负差额说明和期间未结束标记。负的原始收入/支出保留数字，不画正向条。月份可进入对应自然月明细。
- 一级分类按金额排序、点击展开二级分类；各层级金额、笔数、占比对齐，分母统一为本期间、本币种总支出。比例条仅表达正占比、视觉上限 100%，原始正负数值和实际比例保留；退款可能导致占比超过 100%。展开区支持查看一级分类全部账目与二级分类账目。标签不画比例条，不累计为总支出。
- 常用筛选为年/月、类型、原始备注搜索；更多筛选保留账本、币种、自定义日期、一级/二级分类、无二级分类、标签。自定义范围优先于年/月，状态行显示实际生效范围与条件；清除全部筛选恢复全部时间及全部类型（保留当前账本、币种）。
- 财务 URL 查询保存 tab、ledger、year、month、currency、from/to、全部明细条件及 page；刷新与浏览器返回恢复它们。下钻增加来源返回按钮，保留原期间、分类展开状态和滚动位置。滚动仅存当前进程内存，刷新后不保证恢复。
- 生活与财务使用同样的轻量面包屑。生活 tab、领域、里程碑筛选写入 URL，财务入口携带生活上下文，返回生活恢复原视图；全局侧栏不改动。
- 读取失败支持重试、请求序号保护旧响应；列表显示到分钟、截断长备注，详情仍完整只读。数字等宽，窄屏图表改为两列，表格只在自身横向滚动。

第二轮新增合成核验：重复文件再次导入、部分导出更新且保留历史、跨账本 ID 隔离、月份/一级与二级分类汇总和明细逐笔金额一致、多标签与重复标签不污染总支出。浏览器回归覆盖 URL 与分页恢复、清除、月度/分类/标签下钻、返回来源、生活视图恢复、快速筛选旧响应保护、失败重试及宽窄屏分析/筛选。
