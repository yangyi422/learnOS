# 首页最终精修与复用规范

## critique 后的舒展精修

根据首页审查的三个问题，仅调整首页样式、现有可选console材质变量和相关浏览器断言。桌面纵向模块间距28→32px，手机24→28px；保留内容宽度、首排8:4、次排1:1自然等高与卡片内部适度留白。

探索标题20→19px、行高1.6，内容间距8→10px。手机通过原有网格将图标与课程名称放在同一行，其余内容跨满两列，完整标题不再持续缩进；标题/摘要/状态/操作顺序与点击行为不变。手机页头仅首页覆盖公共组件布局：标题跨列、日期与快速记录同行，页头下距36→28px，按钮保留44px触控高度。

普通表面alpha浅色.60→.50、深色.55→.50；痕迹浅色.35→.26、深色.32→.30。普通顶部薄光浅色.12→.08、深色.02→.015；浅色普通hover .70→.62，痕迹hover仅混入15%普通填色，避免交互时跳级。主卡透明渐变、紫色背光、持续环境光、文字色和连续1px边框沿用原值。未新增业务、API或数据库变更。

浏览器回归沿用隔离合成数据，补充手机正文完整宽度、图标/课程同排、日期/快速记录同排和触控尺寸断言；修正既有资料库跳转期望为真实的/explore/library路由。

验证：类型检查、16文件35项单元测试、生产构建通过；首页相关29项Playwright通过，覆盖两主题×1920/1440/1024/390、多项目/单项目/空态、长任务、边框连续性与快速记录。实际查看本次新生成的1440/390px深浅主题全页截图及手机空态，未发现文字裁切或边缘断裂。四张主截图归档在git忽略的data/design-previews/home-critique-polished-{light|dark}-{1440|390}.png。Impeccable检测无命中，git diff --check通过。构建仍有既有大chunk提醒；未验证Safari/Firefox和真实设备模糊性能，未部署或提交。

## 实施范围

检查首页、AppShell、PageShell、SectionHeader、EmptyState、WorkspaceIcon、Element Plus映射、现有主题变量、DESIGN.md和ui-design。第二排原align-self:start阻止拉伸；第一排260px最小高度、28pxpadding和多段间距形成无效留白。

首页改为桌面双栏stretch、单栏start，移除第一排业务卡最小高度，通过20px上下/24px左右padding和14pxgap自然收紧。今天数量改为dl三个分组，数字23px/说明12px，无嵌套卡或按钮。仍使用doing/due/next原始数组长度；逾期颜色复用dueDays，不以颜色规则改变数量。图标优先原图标，空值/空白/占位圆点回退首个Unicode字符（空标题为“项”）。

成熟表面值从首页移入现有workspace-theme.css可选--console-*语义变量，Home保留兼容别名，AppShell首页背景使用同一canvas/ambient变量。现有--surface-glass与全局业务映射不重定义，其他页面不自动采用新材质，不新建主题体系或组件。共享尺寸沿用radius/space变量，图标32px/8px；辅助色仅console-muted由#BCB0CB提至#C4B8D1。

主卡光源中心仍在下沿，椭圆144→192px高、水平8%→16%内缩，模糊12→16px，中心alpha深色.62→.53、浅色.24→.21，衰减更集中；环境光位置/强度不改。不使用硬高度、伪造内容或整体opacity。业务、API、数据库与导航保持不变，之前未提交改动保留。

根DESIGN.md增加落地语义表、公共组件用法及逐页迁移边界；局部主光仅用于重点区，普通页面不得逐卡加光。

## 首页边框专项收尾

本轮仅检查边框与光效层级。接手时工作区已有四边同色基础边框、内侧高光和主卡光晕分层的未提交修复，保留并验证该实现；将五张卡片重复的border/radius声明收敛为一条基础规则，重点、普通、次级和弱化卡片只通过变量选择边框强度，移除闲置hover边框别名及无颜色变化的border过渡。

问题机制是将上下沿高光强弱当成轮廓，以及光晕与表面层级混用，会造成底边过弱、浅色顶部偏白。最终基础边框始终为连续1px同色实线；装饰不使用mask或额外描边，普通卡片高光在内侧且圆角减1px；主卡光晕z-index:-2，透明表面为-1且不画边框，保留外溢光与原透明度。主卡为中性偏灰边缘，没有提高紫色描边或不透明底色。hover只改变普通卡片表面，不改变边框或几何尺寸。

修正边框测试对outline的误判：outline-style:none时计算宽度仍可为3px，应检查样式是否实际绘制。使用隔离合成数据及2倍像素截图，检查深浅主题五张卡片默认/hover的四边颜色、1px宽度、16px圆角、尺寸和光效层级，并验证快速记录仍可操作。已查看放大后的深色主卡与浅色今天卡片，底边与圆角连续。类型检查、35项单元测试及构建通过；构建保留既有chunk体积提醒。未验证Safari/Firefox。

## frontend-design 截图复核与层级精修

遵循DESIGN.md产品落地规则和上一轮仅边框/光效范围，落实三个特征：完整克制的1px轮廓、玻璃后方的局部背光、深浅主题与窄屏稳定的视觉层次。沿用中文字体、配色、文字尺寸、布局及业务，不采用skill的新字体或营销页尺寸建议。

实际查看第一轮1440px与390px浅色全页截图，发现窄屏主卡左下圆角及底边仍过淡：卡片自身isolation:isolate使负z-index伪元素依旧在自身border之后绘制，之前仅检查计算样式无法捕捉这个合成问题。增加透明focus-card-frame承接原网格跨度并建立隔离上下文，卡片不再自身隔离；负层光晕与透明玻璃膜在外层上下文中先于卡片本体border绘制。保留原光晕尺寸、位置、alpha和模糊，不依靠加粗边框、mask裁切或实色遮光。加载状态采用同一结构。

普通卡片背景限制到padding-box，消除默认/hover填色参与边框混色；痕迹边框alpha浅色.07→.095、深色.045→.07，仍弱于普通面板。仅首页使用这些可选变量。DESIGN.md边缘规范同步为四边同色基础边框、独立高光和只过渡表面，纠正旧上下边分色说明。

测试增加背景裁切与外层隔离断言，保留默认/hover四边1px、圆角、尺寸不跳变及双主题2倍截图检查；使用Playwright Chromium和合成数据，不访问正式数据库。跨浏览器和真实移动设备性能仍未验证。
