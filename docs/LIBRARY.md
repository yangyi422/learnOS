# 我的资料库 V0.1

## 使用与结构

入口：探索 → 我的资料库，路由 `/explore/library`。无需创建 AI 学习领域即可使用，也不新增一级侧栏。

专题 Collection 是主题单位；分类只是首页筛选元数据。每个专题允许根目录页面和一层 Section 分组，无父分组字段。Page 使用稳定数字 ID，移动和改名不改变内部链接。通用、Wiki、菜谱共用同一套模型和 Markdown 编辑器，模板只生成新页面的可编辑正文；Wiki 目录与卡片清单随时切换，已有内容不变。

默认阅读，编辑才显示表单；保存失败保留输入，切页/离开有未保存确认。Wiki 目录分页 50 条，专题内按分组过滤、搜索并保持 URL 中的关键词、分组和页码。空专题不写入演示内容。非空分组不能直接删除，可以显式确认将页面全部移回根目录，更新页面版本后删除分组；整个操作事务提交。删除专题需确认全部内容，事务清理页面和分组，不留悬空行。

## Schema 26

新增 `library_collections`、`library_sections`、`library_pages`。专题包含用户归属、名称、说明、可选分类、初始模板、展示模式、封面 URL 和时间。页面包含专题 ID、可空分组 ID、标题、Markdown 正文、标签 JSON、来源 JSON、可选封面 URL、版本和时间。SQLite 外键：专题对子表 CASCADE，页面到分组 RESTRICT；服务端同时验证专题归属和分组所在专题。

沿用 AutoMigrate 和迁移前整库备份。全量数据库备份/恢复包含三表，原业务表保持不变。页面与专题修改使用版本校验防止旧表单覆盖新内容；分组重命名不改页面。

所有 API 位于原认证组 `/api/v1/library/collections`：列表/创建；`/:collection` 详情/修改/删除；`/:collection/sections` 创建及 `/:section` 修改/删除；`/:collection/pages` 列表/创建及 `/:page` 阅读/修改/删除；`/:collection/links?ids=...` 批量检查同专题内部链接；`/:collection/export` 导出 ZIP。所有 ID 校验归属，所有删除必须 confirm=true，页面与专题删除还校验 version。错误响应不泄漏数据库错误，仓储不记录内容，访问日志跳过资料库路径。资料不会发送给 AI。

## Markdown、图片与链接

使用 marked 的 GFM 支持标题、列表、待办清单、表格、引用、代码块、链接、图片、强调和删除线；DOMPurify 使用显式标签/属性允许列表。脚本、事件属性、样式、表单、iframe、SVG、危险协议及不在 HTTP(S)/严格私有本地图片地址范围的图片均不能执行。待办复选框只读，代码块无额外语法高亮依赖。

外部来源复用 SafeExternal，支持 HTTP(S) 和只读 Obsidian 打开链接；多条来源各含 URL、名称、备注。页面内部链接格式 `[名称](/explore/library/专题ID/pages/页面ID)`，可复制后粘贴。仅同专题稳定 ID 被识别；批量核实归属与存在后启用。目标删除时保留文字并显示不可访问，网络错误不会误称为已删除，重新读取可重试。

V0.1.1 正文支持本地上传；页面和专题封面可填写 HTTP(S) URL 或已上传图片的稳定私有地址。外部图片使用 no-referrer，长期可用性由来源决定；本地图片保存在现有 Docker `/app/data` 持久卷，详见下文。

## 搜索

在当前专题的标题、正文、标签 JSON 上参数化 SQLite LIKE。支持中文子串，转义 `%`、`_` 和 `\`，不把用户关键词当 SQL/通配符。每页 50 条，按更新时间和 ID 倒序，结果包含分组、标签和正文摘要。第一版不分词、不做拼音/繁简转换、相关性排序或向量索引；LIKE 子串需扫描该专题文本，数万篇大正文时应后续评估 FTS。标签搜索是 JSON 文本匹配，某些引号/转义字符不等价于显示文字搜索；一般中文标签正常。

## 导出

专题导出为 ZIP：`README.md` 目录，`metadata.json` 完整专题、分组、标签、来源和时间，`pages/数字ID.md` 正文与外部来源。数字文件名避免重名和路径注入；同专题存在的规范内部链接改写为对应相对 Markdown 文件，重命名和移动后仍能离线浏览。外部图片仍是 URL，导出不下载第三方内容。

系统现有 JSON 导出也包含三表，Markdown 全量导出包含专题页面正文及来源。无需依赖 LifeOS 即可阅读主要正文，不自动抓取整篇文章或生成 Obsidian 文件。

## 首版边界

无通用附件上传、自动抓取、AI、双链图谱、无限目录、共享/发布、购物清单、营养计算或 Obsidian 同步。待办清单在阅读时不可直接勾选，需编辑 Markdown 后保存。大量页面通过分页与搜索导航，未实现拖拽排序。

## V0.1.1：本地图片

Schema 28 增加 `library_images`：随机 128 位 ID、用户归属、不可变存储名、MIME、字节大小、宽高、SHA-256、原始名称与创建时间。SQLite 保存元数据，原图保存于数据库同级的 `uploads/library/<ID>.png|jpg|webp`。已有专题、分组与正文保持不变。沿用 APP_DATA_DIR：默认生产目录 `data/prod/uploads/library`；Docker 内 `/app/data/uploads/library`，由原 DATA_HOST_DIR 挂载持久化，不新增公开静态目录或第三方存储。

图片 API：认证 `POST /api/v1/library/images`（multipart 单个 `image`）；认证 `GET /api/v1/library/images/:ID`。原始名称只作为去控制字符的展示元数据，文件名和路径均由服务器生成。支持 PNG、JPEG、静态 WebP（[Go 官方 x/image 解码器](https://pkg.go.dev/golang.org/x/image/webp)，固定 v0.47.0）；拒绝 SVG/GIF/损坏文件。服务端先 DecodeConfig 检查最长边 12000px、总像素 2400 万，再实际解码；单张 10 MiB，保持原始编码与清晰度，不做有损转换。单进程共享文件锁串行解码/写入与清理，文件采用 O_EXCL、同步落盘，数据库失败清理文件，私有元数据查询禁用 SQL 正文日志。

存储默认上限 2 GiB、最多 20000 个图片记录（含待引用上传）；`LIBRARY_UPLOAD_QUOTA_MB` 可调整物理磁盘配额，默认 2048。异常或持续上传不能无限填满磁盘。正文引用使用 `/api/v1/library/images/<ID>`；复用浏览器同源 HttpOnly 会话 Cookie，不在地址中携带 Token。读取校验归属、大小及哈希，响应设置精确 MIME、nosniff、private/no-cache + ETag 条件校验、同源资源策略。上传/清理拒绝跨站及不匹配 Origin 的浏览器请求，现有 Cookie SameSite=Lax 保持不变。反向代理必须保留实际 Host；不根据不可信 X-Forwarded-Host 放宽检查。

编辑器支持选择图片、剪贴板图片粘贴及 textarea 内文件拖放，一次上传一张。文本粘贴仍走浏览器原有行为；上传期间可继续编辑，插入位置随前面的正文修改调整，避免用旧正文覆盖新输入。失败不插入引用，可重试。上传期间禁止保存、切换预览/页面及离开。刷新未保存编辑仍是未保存草稿；文件会暂时保留。正文和预览共用安全渲染器，仅放行严格的本地图片地址或既有 HTTP(S) 图片，支持点击/键盘查看大图，原比例与加载失败重试。

不会在页面删除或去掉引用时自动删除文件。用户可在专题工具栏确认“清理未使用图片”：跨所有已保存页面和封面检查引用，仅清理上传超过 7 天且无引用的记录，并清理同样超过 7 天的无元数据遗留文件。未保存的草稿不算引用，界面要求先保存草稿并确认备份；任何已保存页面仍在使用的图片不清理。读取、页面保存、专题导出、备份和清理共用文件锁。首版不开发独立媒体库或定时回收服务。

## 图片导出与整机备份

专题 ZIP 包含 `pages/<稳定页面ID>.md`、`assets/<图片ID>.<扩展名>`、README 和原始 metadata.json。扫描正文中的稳定本地地址，按 ID 去重写入原图，Markdown 地址改为 `../assets/...`；外部 URL 保留。只改导出内容，不修改数据库。缺失、不可访问或哈希不一致的本地图片导致导出明确失败；HTTP 接口先生成临时 ZIP，成功后下载，失败不会返回半份成功文件。正文引用扫描采用保守匹配，出现在示例代码中的本地地址也可能收录。

“系统设置 → 创建完整备份”生成 `learnos-*.zip`：`learnos.db`、`assets/<ID>.<扩展名>` 和 `manifest.json`（格式版本、范围、各文件大小与 SHA-256）。数据库先 VACUUM INTO 一致性快照，再读取该快照中的全部图片记录，包括有效的待引用图片；文件不可变，共享锁阻止清理/上传产生不一致。数据库历史备份 `.db` 继续可列出和恢复，明确显示“仅数据库（不含图片）”。新完整备份可通过管理员认证的下载入口保存到其他设备。升级前及恢复前自动备份在存在图片表时也采用完整 ZIP。不要只迁移数据库：完整迁移应使用完整 ZIP，或在停止服务后同时复制整个数据目录。

恢复请求仍需要输入完整确认文字并优雅重启。完整 ZIP 先在临时目录校验白名单路径、重复条目、文件数量、解压大小、SHA-256、SQLite 完整性和实际图片内容/元数据一致性；拒绝路径穿越与符号链接。限制 20002 条目、数据库 8 GiB、单张图片 10 MiB、manifest 8 MiB、总解压量 32 GiB。校验失败不替换数据库或清空图片。恢复合并不可变图片，同 ID 不同内容拒绝覆盖；旧 `.db` 恢复不清空现有 uploads。完整恢复失败至多留下未引用的安全文件，不删除原有图片。数据库原子替换前自动保存当前完整备份。恢复额外保留的旧图片可由带确认的 7 天清理操作处理。

容器重建只替换程序，DATA_HOST_DIR 的数据卷和 BACKUP_HOST_DIR 的备份卷必须继续挂载。云服务器需要数据卷写权限、备份/临时目录空间，反向代理允许至少 11 MiB 请求体；不要把 uploads 加到 nginx/Caddy 公共静态目录。`.gitignore` 与 `.dockerignore` 排除个人数据、上传目录和备份 ZIP。卡片按需生成小图，见 [图片性能检查](LIBRARY_IMAGE_PERFORMANCE.md)。未开发原图压缩、SVG/动图、视频、云存储、AI/OCR 或图片在线编辑。
