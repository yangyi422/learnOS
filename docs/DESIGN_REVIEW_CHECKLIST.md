# 设计评审清单（LifeOS）

用这份清单做首页/业务界面的设计与质量评审。来源：仓库 `design.md`、`docs/ui-design.md`，以及 `.agents/skills/frontend-design`、`.agents/skills/impeccable`（Operate 模式、craft-floor、layout、distill、polish、clarify）的关键要求。`design.md` 是当前视觉权威；本清单只补充评审动作，不覆盖规范。

## 1. 开始前

- [ ] 读 `design.md` 及相关业务文档，确认没有用历史方案覆盖当前实现。
- [ ] 明确页面模式（LifeOS 业务页 = Operate）与“唯一主任务”。
- [ ] 用一句话写出空间论点：主路径、必须分组的元素、主/次元素、预期密度、各断点如何重排。
- [ ] 列出真实数据来源；不为填充虚构内容。

## 2. 信息架构与布局

- [ ] 眯眼测试：仍能按顺序识别主元素、次元素与主要分组。
- [ ] 一个区域一个主要操作；次要操作用轻量样式，破坏性操作有确认/撤销。
- [ ] 关联内容靠邻近与间距分组，而不是再加一层卡片；不嵌套卡片。
- [ ] 同一实体不在多个区域以相同权重重复；跨区域引用要有明确角色（如“今日焦点”标记）。
- [ ] 空态说明状态并给出下一步；空态不堆叠多个空卡片。
- [ ] 响应式是结构变化（换列、折叠、换序），不是只缩字号；检查 1440 / 1180 / 1024 / 700 / 390。
- [ ] 无横向溢出、控件重叠、图层遮挡；DOM/焦点顺序与视觉顺序一致。

## 3. 视觉与材质

- [ ] 继承现有玻璃、环境光与语义 token；不新增光效、渐变文字、霓虹描边。
- [ ] 阴影有偏移与柔和衰减；不叠加“边框 + 大阴影”的幽灵卡片。
- [ ] 圆角 12–16px（卡片）与胶囊（小控件）；同一角色一致。
- [ ] 强调色只用于主操作、选中与状态，不用于装饰。
- [ ] 深浅主题、自定义色系都检查；正文/辅助文字对比度 ≥4.5:1，大字号 ≥3:1。
- [ ] 层级靠字号、字重、间距、留白，而不是全部加粗或加容器。
- [ ] 标题不配装饰性 eyebrow/kicker；页面标题由内容承担。

## 4. 状态与交互

- [ ] 每个控件具备 default / hover / focus-visible / active / disabled / loading / error。
- [ ] 加载用骨架；失败说明原因并提供局部重试；写入失败保留最后确认状态。
- [ ] 完成态与未完成态交互不同；重复操作幂等；冲突提示刷新后重试。
- [ ] 卡片标题是真实链接，操作按钮独立，整卡覆盖链接不得遮挡按钮。
- [ ] `plan_date`（计划执行日）与 `due_date`（截止日）文案、交互不混用。
- [ ] 高频操作 1–2 次点击内完成；弹窗只在需要选择/保护时使用。
- [ ] 键盘可达、焦点可见、Enter/Space 行为正确；移动端触控目标 ≥44px。
- [ ] 尊重 `prefers-reduced-motion`；动效只表达状态变化，不做统一入场动画。

## 5. 文案

- [ ] 按钮说清动作与结果（“加入今天”“移出今天”“继续上次”），同一概念前后用词一致。
- [ ] 错误说清：发生了什么、为什么（可确定时）、如何恢复；不暴露内部错误码。
- [ ] 每个想法只说一次；标题已说明的不要再加引导句。
- [ ] 语气克制，不因任务数量变化；生活场景允许留白，不制造 KPI 语气。

## 6. 验证

- [ ] `npm run typecheck`、`npm run test`、`npm run build` 通过。
- [ ] 相关 E2E 子集先通过，最后跑完整目标集；不把未执行或失败测试说成通过。
- [ ] `CAPTURE_VISUALS=1 npx playwright test e2e/visual-audit.spec.ts` 生成截图，按批一次检查桌面深浅、平板、手机、空态/完成态（4–6 张关键图）。
- [ ] 检查 200% 缩放、长标题、空数据、错误数据、慢加载。
- [ ] 清理死 CSS/未使用组件、调试输出、临时脚本；不改无关文件。
- [ ] 更新 `design.md`（当前规范）、`docs/ROADMAP.md`（本轮范围与验证）；业务语义变化同步对应文档。
