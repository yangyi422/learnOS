# 设计评审清单（LifeOS）

本清单复用 [AGENTS.md 的日常视觉流程](../AGENTS.md#日常-ai-前端视觉流程默认执行)，只补执行核对项；[design.md](../design.md) 是唯一当前视觉规范，[ui-design.md](ui-design.md) 的历史方案不得反向覆盖它。适用于日常操作与阅读界面，不是营销展示页模板。参考研究优先使用可用的 refero-design；frontend-design / impeccable 补充实现、可访问性和批量复核方法，不另立风格权威。Skill、MCP、自动审美工具缺失时明示，不伪造调用、不强制安装。

## 1. 开始前：锁定本轮，不重设计全部

- [ ] 读当前规范、目标页、主题 Token、公共组件 props / slots 与相关 E2E；先记录未提交修改，不 reset / clean / stash 他人的工作。
- [ ] 明确目标路由、主任务、想改善的问题、允许变化与必须保持项；用户没给参考时，以已验收页面为参考，不要求填写冗长模板。
- [ ] 实际读取提供的链接/图片：Style 决定视觉语言，产品 Screen 决定布局/密度，Flow 决定路径；不可只看摘要就声称看过参考图。
- [ ] 用 3–5 条「参考特征 → 现状差异 → 本轮动作/不采用项」锁定一个主方向；不平均混搭风格，不复制营销 Hero、品牌墙或装饰。
- [ ] 实施前采集当前基线，标记 URL、light / dark、视口、fixture/真实数据、固定时间、浏览器、DPR 与服务资源。基线与修改后用不同目录，实际看图比较，不只计算像素差。

## 2. 修改优先级与实现限制

**布局结构与信息层次 > 组件视觉语言 > 阴影、光效及微动效。** 先诊断优先级，不等于默认授权改布局。

- [ ] 眯眼仍能分辨主要内容、分组和下一步操作；关联内容用邻近/间距分组，不再套卡。
- [ ] 层级用字号、字重、分组和留白，不靠一张特殊发光卡或全部加粗。首页六卡保持同材质，内容承担主次。
- [ ] 先查现有组件契约、Element Plus 内层节点、scoped / :deep、CSS specificity、继承、Teleport 挂载点、伪元素叠层，再决定改动位置。
- [ ] 局部变量限定在页面/路由作用域；不为一页修改 `:root`、共享玻璃别名、全局 `.el-*` 或 PageShell / AppShell。不引入新依赖或新渲染引擎。
- [ ] 材质不生效时检查 computed style、mask / backdrop / z-index、命中规则及实际加载资源，不重复叠加覆盖规则或只微调 alpha。
- [ ] 阴影有偏移、低强度、柔和衰减；不新增彩色光斑、强渐变、暖色混搭、白顶线或霓虹包边。
- [ ] 不对内容容器应用 opacity / mask / blur 制造玻璃；材质层与可读内容分开，不用 overflow 隐藏溢出来掩盖布局错误。
- [ ] 圆角、控件状态和文本角色复用实际 Token；首页局部参数不变成全站标准。保持用户保存的 theme / accent，不重置偏好。
- [ ] 不修改无关页面、业务逻辑、数据结构或真实数据；用于测试的合成资料明确标为 fixture。

## 3. 状态与可访问性

- [ ] 对受影响控件检查 default / hover / focus-visible / selected / active / disabled / loading / error；不要求无关组件重复验收。
- [ ] 空态说明状态与下一步；错误能重试且不丢最后确认状态；完成态不再显示不适用操作。
- [ ] 链接真实可达；整卡覆盖链接不挡按钮；键盘顺序、焦点返回、Enter / Space、Escape 与移动菜单可用。
- [ ] 手机关键触控目标至少 44px；长标题、长列表、空数据、慢/错响应不撑破布局；检查缩放和实际断点。
- [ ] 正文/辅助文字与 placeholder 对比度至少 4.5:1，大字号至少 3:1；弱边界不等于无焦点提示。固定背景截图抽样不等同完整 WCAG 审计。
- [ ] 深浅主题均验证，影响交互色时加自定义色系；减少动态偏好继续工作。静态截图不能证明动效流畅，改光效/动画时另测滚动与生命周期。
- [ ] `plan_date` 与 `due_date`、用户内容、权限和业务状态语义保持不变；不为了视觉统一改实际概念。

## 4. 复用现有测试，不另建平台

在 `web/` 运行，实际命令与浏览器选择见 [本地开发说明](LOCAL_DEV_NOTES.md#视觉工作流的日常命令)。

| 影响面 | 复用测试 | 需要看到的证据 |
| --- | --- | --- |
| 首页日常视觉 | `npm run test:ui`：visual-audit + home-material | 双主题桌面/手机、平板、三场景、空态/完成态截图；六卡一致、控件状态、路由隔离、静态降级 |
| 首页内容/布局/操作 | workspace + daily-focus + planning | 受影响业务行为与布局断言；不只跑截图集 |
| 公共组件、根级 Token 或主题 | ui-foundation + regression，再加对应页面 spec | 核心路由、跨断点、深浅/自定义色系与非目标页无回退 |
| 项目、资料库、学习、生活等局部页 | projects / library / library-images / learning-conversation / life 等对应 spec | 必须有目标页的前后截图和操作；首页截图不能替代目标页验收 |
| Ambient / 动效 / 材质能力 | home-ambient + glass-refraction / pilot-effects 等相关 spec | Reduced Motion、CSS / WebGL 互斥、Context/监听清理；不要只拿静态图判流畅 |

- [ ] 前端常规门槛：`npm run typecheck`、`npm run test`、`npm run build:check`，并运行相关 E2E；隔离构建不覆盖已有嵌入产物。
- [ ] 至少 light / dark × 1440 / 390；涉及断点补 1024 或真实断点。只改一个主题也要检查另一主题不回退。
- [ ] `visual-audit` 使用合成 API 数据、固定日期/时区与静态动效，默认保存首屏/整页 PNG 和上下文 JSON。其他页面复用各自 fixture 并按同样条件截图。
- [ ] 同浏览器、字体、DPR、数据与时间做前后比较。截图范围、状态或来源改变不能算像素回归证据。
- [ ] 基线与修改后目录不同；并行 Playwright 进程必须不同输出目录，避免 ENOENT/trace 丢失。不要自动更新截图 goldens 以消除失败。
- [ ] 验证运行环境时指定实际 URL，并核对新 CSS/JS；临时 Vite 页面正确不代表 Go 嵌入版本已经更新。

## 5. 有限自动修正与停止条件

- [ ] 初次修改后批量看图，列出最多 3 个最高优先级差异；先修布局/遮挡/可读性，再修组件，最后装饰。
- [ ] 最多 **2 轮** 自动「定位 → 修改 → 同条件重拍」；每轮仅修本轮范围内明确的问题，不散射式改参数。
- [ ] 达标立即停止。预算耗尽、无可辨改善、需要超范围改动或无法获取真实浏览器证据时停止并报告，不继续微调。
- [ ] 失败先定位：环境、fixture、过期断言、实际回归分别记录；修环境后重试必须保留真实退出码，未证实“历史失败”前不能下结论。
- [ ] 未经授权不挪页面来满足旧测试，也不删除正确断言把回归改成通过；先核实当前规范、用户意图与已验收基线。

## 6. 收尾与报告

- [ ] 清理本轮调试代码、重复 CSS 和无关改动，保留他人的未提交修改；截图、trace、报告留在忽略目录，不提交个人资料或凭据。
- [ ] 全局规则变化才修改 [design.md](../design.md) 的当前条目；局部修复只更新相关测试与 [阶段记录](ROADMAP.md)，不追加第二套规范。
- [ ] 简洁汇报：改了什么、参考来自哪里、实际用了哪些 Skill、做了哪些设计检查、已通过/失败/未执行，以及还差什么。
- [ ] **构建成功、自动测试通过、截图存在、Agent 已看图、用户最终认可，是不同事实。** 不把其中任何一步冒充全部完成；不能宣称读过 Skill 就完成审美复核。
- [ ] 明示浏览器/设备覆盖；没验证 Safari、Firefox、真机、真实私有数据或动画就写未验证。剩余差异具体到区域与原因，而非“已完美复刻”。

最简单的任务描述：**「优化［页面］的［问题］，参考［可选链接/图片］，保持现有风格，按项目视觉流程直接做。」** 无参考则以当前规范和已验收界面为主参考。
