# LifeOS V0.3-A：月度生活回顾

入口 `/life/reviews?month=YYYY-MM`，仍属于生活空间，与时间线、目标、财务平级，不增加全局侧栏。按月阅读项目与行动、学习与探索、生活经历、财务与资产和实际目标阶段变化；无记录不评价生活价值。不调用 AI 或第三方服务。

## 月份与事实来源

第一版明确采用 `Asia/Shanghai` 自然月。时间戳用当地月初转换 UTC 查询 `[start,end)`；文本日历日期保持原语义，不经 UTC 转换。每个事实版本保存 timezone、月份起止、生成时间、进行中状态和统计限制。

- 任务：仅当前 done 且有 `actual_completed_at` 的记录，归属真实完成时间。既有 `completed_at` 曾由迁移以 updated_at 补值，无法区分可靠历史，所以保留原字段及旧数据，新增可空 actual_completed_at，从本轮之后真实完成动作捕获。创建已完成任务、普通状态更新和看板移动均记录，重开清空，重命名与排序不重置日期。
- 项目：新增可空 completed_at，今后显式完成时记录；重复 completed 请求和普通文字修改不重置，归档保留，重新激活清空。旧完成项目不补日期。
- 课时：新增 completed_at，在原 AdvanceLesson 事务的完成动作中记录，幂等重放保留。跳过不是完成，不计入完成课时。旧完成课时没有可靠日期，排除完成汇总。
- 正式结业：课程新增 completed_at，沿用原 Graduate 条件及事务，仅今后首次正式结业记录，旧 completed 不回填；重复结业保留日期。
- 学习活动：原 LearningTurn.created_at 按月，同一课时合并显示最近一条活动；本月已完成课时不再另列其回答活动。不读取浏览行为、不用回答次数推断掌握；不保存问题/用户回答全文到回顾。
- 探索：原 ExplorationQuestion.created_at 仅表示记录了问题，不推断解决时间或完成。没有可靠时间的其他活动不展示。
- 生活经历：occurred_on，补录创建日期不改变月份。与本月可靠项目完成/课程结业指向同一 ID 的生活收录合并到成果条目，保留生活标题、描述、领域、里程碑与原生活入口，避免重复展示。
- 长期目标：仅 LifeGoalEntry.occurred_on 的阶段、决定与状态前后值；不读取最新状态冒充当月变化，不将资产关联当作进展。
- 收支：在同一读事务中复用 FinanceService.Summary，按账本和币种分别读取当月，金额仍是整数分。不合并不同账本以免重复来源；不同币种也不累计。数据不足以证明完整，期间未结束明确提示。无当月交易使用“暂无账本数据”，不给出已核实为零的结论。记录账本 ID、名称、币种、实际覆盖、最近导入与主要分类。不复制新计算逻辑。
- 资产：沿用 AssetService 的真实日期、NULL/零、范围及计算规则，列出每份记录，不推算月末余额；不完整用已填合计和范围差额，无快照不显示净资产。

实时预览使用当前数据库状态；任务或项目重开后不会保留其旧完成月份的完整状态历史，本轮未新增状态事件总线。需要可靠保留某月事实时应显式保存回顾，之后原业务变化不改写已保存内容。旧时间不足的记录仍可通过用户已确认发生日期的生活事件回顾。

## 保存、版本与个人心得

Schema 25 两张表：

- `monthly_reviews`：user_id/month 唯一，facts_id、三个可空白个人文本、外部笔记 URL、version、created_at/updated_at。一个月份只有一份当前正式档案。
- `monthly_review_facts`：不可变事实 JSON、user/month、base_version、generated_at、confirmed_at；重新采用新版本时保存旧版对应的个人文本副本 ArchivedPersonalJSON。旧事实版本仍可阅读，不覆盖或删除。

首次打开没有档案时请求服务端生成预览，事实 JSON 由后端各模块读取，客户端不能提交统计数据。生成不等于正式保存；待确认预览以 ID 引用，24 小时内可保存，过期要求重新读取。当前版本只读冻结事实，个人心得可独立编辑。

重新汇总生成新预览并保留当前填写的心得；原正式版本不变。用户可取消返回原版本；确认时原事实与当时已保存心得留档，再采用新事实和当前输入。保存使用版本校验及唯一约束；相同请求重试返回原结果，旧页面不得覆盖不同的新内容。任何事务步骤失败全部回滚。

三个心得都可以为空，每个最多 10000 字。可保存已有 Obsidian/http/https 笔记链接，复用 internal/links 和 ExternalLink。不自动写文件、发布笔记或把下月关注转为任务。未保存离开或切月需确认，保存失败保留输入。

## 来源与隐私

摘要和金额在版本中冻结；原始来源是否可用由读取时的归属校验计算，不修改冻结事实。来源删除或不可访问时保留摘要并禁用原入口，提示来源不可用。原始来源后续修订也不会替换保存的标题、金额和状态。

所有 API 在原认证组中，生成、保存、历史版本都校验当前用户和月份。回顾路径不进入访问日志，仓储使用 logger.Discard，错误响应不输出 SQL/私人文本或堆栈。未确认预览也属于私人数据，仅当前用户或现有受保护备份可读取。

API：

- `GET /api/v1/life/reviews` 已保存月份。
- `GET /api/v1/life/reviews/:month` 当前正式回顾（不存在则 review=null）。
- `POST /api/v1/life/reviews/:month/preview` 生成新的独立预览，不更新正式回顾。
- `PUT /api/v1/life/reviews/:month` facts_id、version、三段个人文本、external_url、confirm_replace；已有档案更换事实 ID 必须显式确认。
- `GET /api/v1/life/reviews/:month/history/:snapshot` 仅已确认版本，返回当时事实和更换前保存的心得。

整库迁移前备份、备份恢复自动覆盖两表和新增日期；JSON 导出包含完整事实及历史，Markdown 导出当前回顾心得和冻结事实 JSON。旧字段、账目、阶段和资产均保留。待确认预览第一版不自动清理，长期高频重汇总可累积少量待确认记录；以后可增加保留策略，不影响当前正式档案。

## 版本边界

不做年度、AI 心得、评分、排行、打卡、资产推算、社交分享或复杂文档版本控制。固定统计时区不能按用户浏览器自动切换；多个账本/币种独立展示。暂无旧任务完成时间的可靠追溯、重复完成的事件历史或旧课程结业日期推断。原始数据本身的完整性仍由用户确认。
