# LearnOS 工程加固与验收

## 范围

本轮只收紧已有功能的请求生命周期、缓存、重复写入防护、失败原子性、任务恢复、长列表渲染和一致性检查，不改变课程、推荐、掌握度或误区判定规则，不新增产品功能。

## 性能边界

- 知识地图仍只为已展开区域创建节点 DOM；折叠区域只保留概要标题。
- 节点关系和认知详情按需读取，并按 Lesson 在当前页面会话内缓存。切换路径/列表视图不重读图或已读详情。
- 探索雷达以 `course_id + lesson_id + limit` 为缓存键，TTL 为 60 秒。领域、Lesson 和参数不同时不共享结果；保存/撤销探索问题、提交学习证据、切换当前 Lesson、应用课程草案或创建新领域时主动失效受影响缓存。
- 问题池首段只渲染 20 条，用户按 20 条继续展开；后端仍保留查询上限。
- 学习页的关系、认知详情和误区读取由串行改为并行，其中任意辅助面板失败不阻断核心回答流程。
- 知识地图、学习页和探索页在切换或卸载时会取消无效读请求；主动取消不会被误报为网络故障。

### 可重复的性能对比

| 固定回归场景 | 加固前 | 加固后 |
| --- | ---: | ---: |
| 同一节点在路径视图与列表视图各选一次 | 图 1 次，详情 2 组 | 图 1 次，详情 1 组 |
| 探索领域 A → B → A，结果未变 | 雷达 3 次 | 雷达 2 次 |
| 45 条问题的首屏 DOM | 45 条 | 20 条（减少 55.6%） |
| 学习页 3 组辅助数据 | 3 次串行等待 | 3 次并行，关键路径为最慢单请求 |

上表是浏览器回归 fixture 中的确定性请求/DOM 计数，不是特定机器的绝对耗时 benchmark。

## 稳定性与一致性

- 回答、迁移挑战生成和挑战作答使用客户端生成且数据库唯一的幂等键；同一键不同载荷会拒绝为冲突。
- Curriculum Draft 以生成范围的数据库部分唯一约束防重，Blueprint Unit Expansion 以条件状态更新抢占；快速重复点击不会启动第二份正式数据。
- 课程草案在 Provider 超时或结果解析失败时将生成占位记录标记为失败，不写入正式 Lesson；后续重试新建独立草案。
- 刷新后会恢复未 Apply 的领域初始化草案；课程档案能读取 `generating` 占位并轮询至终态。
- 一致性检查新增 Course/Unit/Lesson 归属、统一节点类型、MasteryRecord 分数与归属、CognitiveState/LearningTurn 及 CognitiveEvidence/LearningTurn 交叉归属检查。检查仍只读，不自动删除或修复数据。

## 数据库迁移与回滚

本轮没有新增列、表或索引，`CurrentSchemaVersion` 保持 14，不会触发新迁移，也不会改写现有学习数据。

现有 Schema 13 是加法幂等/证据快照迁移；Schema 14 是稳定 Blueprint Unit ID、问题优先级和误区审阅迁移。启动时在 schema 升级前自动生成 SQLite 备份。如需回滚：

1. 停止应用，保留当前数据库和备份目录。
2. 优先通过设置页选择升级前备份，输入完整确认文字；系统会再备份当前库，重启时原子替换。
3. 或使用 `restore-backup` CLI 验证 `integrity_check` 后恢复。不要手工删列或使用旧应用直接改写新库。

## 已知边界

- 普通回答和挑战已是持久化 request-ID 幂等；领域初始化、Curriculum Draft、Blueprint Unit Expansion 和 Exploration Direction 目前使用“业务范围唯一键/状态抢占/方向身份”防重，还没有统一的持久化 AI request ledger。
- 浏览器刷新能恢复已持久化阶段或轮询正在生成的占位；进程被强制终止后不会在新进程中继续旧 HTTP 请求里的 Provider 调用，需要用户幂等重试。
- 问题池已分段渲染，但还不是数据库游标分页；单用户现有上限下可用，数千条问题时需补服务端分页。
- 真实 DeepSeek 故障、进程级崩溃恢复、长时间运行、真实备份回滚以及屏幕阅读器/高对比模式仍需人工验收。
