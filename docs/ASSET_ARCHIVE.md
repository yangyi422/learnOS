# LifeOS V0.2-B：资产档案

入口：生活 → 财务档案 → 资产档案，URL `/life/finance?tab=assets`。资产状态由用户在某个日历日期自行记录，与钱迹收支独立，不从收入、支出或收支差额推算余额。不调用 AI、银行、行情或其他第三方服务。

## 数据与计算契约

第一版只支持 CNY。银行存款、支付平台余额、投资资产、其他资产和负债总额均可选，至少填一项。输入非负人民币元，最多 10 位整数、2 位小数，后端复用精确十进制解析器转换整数分；前端用 BigInt 计算，只有绘图坐标转换为浮点像素。

- 空白保存 NULL，含义为“未记录”；明确填写 0 保存整数零。不以 NULL 推断已核实没有资产或负债。
- 资产总额为四个资产类别之和。不完整范围显示“已填资产合计”，仅累加已填写金额；所有资产类别均为空时合计为空，不以负债记录推断零资产。
- 负债已填写且至少填写一类资产时计算已填资产合计减负债。范围完整时称为“净资产”，否则称为“已填范围差额”。未填负债时差额为空。净资产允许为负。
- 完整范围由四个资产类别和负债全部非 NULL 自动判定，不接受客户端声明完整。未核实类别应留空；确认无余额才能填 0。
- “其他资产”采用用户合理估值，避免与银行、平台或投资资产重叠；没有独立账户明细参与重复累计。

快照日期保存已校验的 YYYY-MM-DD 文本，不经 UTC 与当地时间互转。默认日期使用浏览器本地当天；允许记录其他真实日期。创建/修改时间是审计时间，不参与历史排序。日期范围为 1900–9999 年，备注最多 1000 字。

## 记录与维护

新增表 `asset_snapshots`：用户 ID、快照日期、五个可空整数分金额、备注、version、created_at、updated_at。按用户和日期唯一。一份快照是独立记录，不属于钱迹来源账本。

- 日期冲突返回 409，不覆盖现有记录。页面保留输入，并提供查看当天已有记录的入口；放弃当前修改需要确认。编辑日期也受唯一性约束。
- 编辑根据 ID、用户及 version 校验；成功 version + 1，保留创建时间，更新修改时间。旧表单不能覆盖新记录；删除同样要求当前 version。
- 读详情优先，编辑和删除按需出现；删除需确认。保存失败保留表单，保存期间禁止重复提交。未保存关闭需要确认。
- 新增可以手动使用按快照日期最新的记录作为模板：复制已填金额与空白状态，保留新日期及当前备注；不复制旧记录 ID/版本，不写入数据库。页面明确提示历史金额非实时余额，必须手动保存。

## 展示与趋势

最新概览是按快照日期排序的最近记录，不声称当前实时资产。最新记录可以是不完整范围，始终显示日期、范围、金额和组成，未知字段显示“未记录”。列表按日期倒序，长备注摘要截断，详情完整显示。

SVG 趋势只包含完整范围记录，横轴采用实际日期距离、纵轴采用整数分金额映射；不补齐缺失月份、不补零、不从收支推算。负净资产正常显示，单条仅显示一个点，无完整范围时解释原因。点可点击或键盘打开详情。连线只连接真实快照；数值提示包含准确金额及日期。不完整记录保留在列表并标注排除数量。

最近两份完整范围快照之差称为两次记录的净资产变化，不解释为投资收益或当期收支结余。修改或删除后立即重算列表、最新记录、趋势和变化。

## API、迁移和备份

现有认证组下新增：

- `GET /api/v1/finance/assets`
- `POST /api/v1/finance/assets`
- `GET /api/v1/finance/assets/:id`
- `PUT /api/v1/finance/assets/:id`
- `DELETE /api/v1/finance/assets/:id?version=N`

写入接受 snapshot_date、bank/platform/investment/other/debt（元的字符串或 null）、note；编辑还需 version。输出所有分金额采用十进制字符串或 null，并返回服务器计算的 complete、asset_total_minor、net_asset_minor 及固定 CNY。服务器拒绝未知字段、数值型金额、无效日期、金额精度/范围错误和超长备注。

Schema 从 22 升为 23，沿用升级前自动 SQLite 快照和可重复 AutoMigrate，只添加资产表和唯一索引，不改写钱迹、生活或学习表。整库备份与恢复自动包含资产表；JSON 导出增加 asset_snapshots，Markdown 展示快照字段与范围。回退需保留升级后的备份，再根据既有流程恢复迁移前备份；不在生产库运行测试或种入示例。

财务 URL 访问日志与 recovery 已禁用私人内容输出，资产仓储使用 logger.Discard；错误响应不暴露 SQL、金额、备注或内部堆栈。用户只能访问自己的记录，无新增复杂权限体系。

## 验证与边界

合成 Go 测试覆盖创建/编辑/删除、精确金额、负净资产、零/NULL、模板独立、同日冲突、日期变更冲突、跨年月排序、用户隔离、旧版本冲突、输入校验、失败回滚、钱迹不受影响、JSON 导出；迁移测试检查 Schema 22 升级和重复迁移保留旧交易/生活/目标，备份和实际恢复检查资产及收支持久化。

前端单元测试核对精确实时计算、模板复制、实际日期、完整范围比较和变化。浏览器测试使用合成数据覆盖空态、单条、创建失败保留、刷新、模板、编辑、删除确认、同日冲突、部分范围排除、趋势点及桌面/窄屏。

暂不做银行同步、实时行情、投资交易、多币种、自动估值、预算/AI 建议或与长期目标深度关联。列表第一版一次读取个人快照历史；多年高频大量记录的分页与图表点密度尚未优化。完整范围只是用户填写了各类别，不代表外部核实、无重复估值或无漏项。
