# 工作台首页 V0.2

## 范围与数据

继续使用 PageShell standard 和现有工作台 Focus、Today、Active Projects、Continue Learning。任务选择、状态、归档、项目统计和课程进度不变；核心 `/api/v1/workspace/home?date=...` 请求只发一次，不等待最近内容。移除首页底部完整 Inbox 输入、历史列表和空卡片，独立收集箱完整保留。

新增鉴权只读 `/api/v1/workspace/recent`，handler → WorkspaceRecentService → WorkspaceRecentRepository；读取原 SQLite 表，不迁移、不新增表、不持久化第二套活动历史。最多读取三个资料页面、两个生活事件、一条目标阶段记录和一个资产快照日期。每个来源失败时返回独立的安全错误，其他来源继续可用；整体请求失败也不影响任务/学习和快速记录。返回 Cache-Control: private, no-store，不发送给 AI，不打印财务数据。资产投影只 SELECT snapshot_date，不读取或返回任何金额、净资产、财务备注。

资料页面联合所属专题限制用户，按页面 updated_at、ID 倒序，返回稳定页面与专题 ID、标题、专题名称、展示模式、封面地址和更新时间，不返回正文。生活事件按 occurred_on、ID 倒序，显示发生日期，补录日期不参与排序。目标只读取正式 LifeGoalEntry 的 occurred_on 及前 100 字内容，关联所属用户的目标；打开目标、编辑目标说明或关联快照都不会伪装为阶段变化。资产按 snapshot_date 取最近记录日期，不声称实时余额或完整范围。

首页合并最多六条：更新时间按浏览器本地时间解释；仅有日历日期的事件/变化按本地当天零点排序，不通过 UTC 日期解析产生偏移；同时明确标注“更新”“发生”“变化”。财务日期和入口不混入时间排序。库内页面进入原专题的 Wiki/Cards 阅读模式；生活用现有 event/goal query 打开详情，不使用标题匹配。

## 快速记录

唯一首页输入入口为顶部 QuickCaptureDialog，复用 InboxCaptureForm 与原 POST /api/v1/inbox（capture_key 幂等）。自动聚焦；Enter 保存、Shift+Enter 换行；普通文字、链接、多个段落都先进 Inbox，不选择模块类型。保存中禁止重复提交和关闭；失败保留输入；关闭/取消及路由离开时有文本则确认放弃，继续编辑保持输入。成功关闭并复用首页查询刷新真实待整理数量，保留原来的 processed/archived 统计口径。没有未处理内容时仅显示“收集箱 · 0 条待整理”，无大块空状态。

## 展示、加载和兼容

最近内容使用紧凑统一列表，可选 48px 缩略图（原 card-v1、lazy/async、私有 Cookie 认证），不请求资料全文、不下载原始封面。缺图隐藏失败图像并保留小尺寸区域，仍可打开页面。来源都为空时省略最近内容区域，资料库、生活、财务和 Inbox 保留轻量快捷入口。错误提供对应重试，不伪造内容；刷新最近内容时清空旧链接，返回首页重新查询删除后的记录。请求有 AbortController 和当前请求判定，卸载后不更新状态，旧结果不会覆盖新查询。

延用原响应式布局、Token 与核心区域顺序，移动端列表和入口换行。没有 Inbox → 资料库转换、仪表盘配置、财务图表或自动总结能力。
